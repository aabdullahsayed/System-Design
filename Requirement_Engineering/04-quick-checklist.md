# 04 - Quick Checklist (Before You Start Coding)

## Understand
- [ ] Problem statement is written and agreed
- [ ] Goals and success metrics are measurable
- [ ] Scope and **out-of-scope** are defined
- [ ] Budget, deadline, and team limits are known

## People
- [ ] All stakeholders identified
- [ ] Main users/personas described
- [ ] One decision-maker (product owner/client) is named

## Requirements
- [ ] Functional requirements listed with IDs
- [ ] Non-functional requirements covered (performance, security, usability, reliability, compatibility)
- [ ] Constraints and assumptions documented
- [ ] External integrations identified (payment, SMS, APIs, etc.)
- [ ] Edge cases and error situations considered

## Quality Check
- [ ] Each requirement is clear, testable, and has acceptance criteria
- [ ] No conflicting requirements
- [ ] No vague words ("fast", "easy", "etc.", "should be good")
- [ ] Prioritized with MoSCoW; **MVP** defined

## Agreement
- [ ] Reviewed with client/stakeholders
- [ ] Prototype/wireframes shown
- [ ] Written sign-off received (baseline v1.0)

## Control
- [ ] Change request process agreed
- [ ] Traceability (requirement -> design -> code -> test) set up
- [ ] Documents are versioned and shared with the whole team
- [ ] Review of requirements scheduled each sprint/phase

---

### Ready to build when:
> Everyone can answer the same way: **What are we building? For whom? Why? What is first? How will we know it's done?**

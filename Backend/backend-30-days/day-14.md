# Day 14: Week 2 Capstone: In-Memory CRUD API

**Week 2 · Web Fundamentals & REST APIs**

## 🎯 Learning Objectives
- Integrate routing, DI, validation, and configuration into one deployable API
- Document the API for consumers

## 📚 Topics
- Swagger/OpenAPI documentation
- API design review checklist
- Manual + automated smoke testing

## 🟣 C# / .NET Focus
- Enable Swashbuckle/OpenAPI (`AddSwaggerGen`).
- Add XML doc comments to controllers for richer docs.

## 🟠 Java Focus
- Add springdoc-openapi (`springdoc-openapi-starter-webmvc-ui`).
- Annotate endpoints with `@Operation`/`@ApiResponse`.

## 🛠️ Hands-On Task
Finalize a complete, well-documented Bookstore CRUD API (in-memory storage) in both stacks with OpenAPI/Swagger docs, consistent error handling, validation, and configuration. Write a short Postman/Bruno collection or `.http` file exercising every endpoint.

## 🚀 Stretch Goal
Add rate-limiting middleware/filter (simple in-memory token bucket) to one endpoint as a preview of production concerns.

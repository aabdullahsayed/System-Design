# Day 7: Week 1 Capstone: Data Structures Library

**Week 1 · Data Representation & Complexity**

## 🎯 Learning Objectives
- Consolidate array, list, stack, queue, and hash table implementations into one library
- Practice writing tests that verify correctness and complexity assumptions

## 📚 Topics
- Code organization for a small library
- Writing test cases for data structures
- Micro-benchmarking basics

## 💡 Core Ideas
- A good personal data-structures library is one of the highest-leverage things you can build early — you'll reuse it for the rest of this course.
- Testing a data structure means testing behavior *and* edge cases: empty, single element, duplicates, large input.

## 🛠️ Practice Exercises
- [ ] Build a single repo containing your own implementations of: dynamic array, singly linked list, stack, queue, and hash map.
- [ ] Write at least 5 test cases per structure, including edge cases (empty, one element, large n).
- [ ] Write a short benchmark comparing your hash map's lookup time to a built-in language map/dict at n=10,000.

## 🎤 Interview-Style Questions
Try answering these out loud, without notes, before checking any reference:

- If you were designing a cache, which of these five structures (or combination) would you reach for, and why?
- What's one design decision in your hash map implementation that trades memory for speed, or vice versa?

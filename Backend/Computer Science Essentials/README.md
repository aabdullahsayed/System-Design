# 30-Day Computer Science Foundations for Engineers

A structured, hands-on plan to build (or rebuild) a rock-solid CS foundation — the kind that makes you a stronger engineer regardless of language or stack, and that holds up in technical interviews and system design conversations alike.

This is **language-agnostic** by design: implement every exercise in whatever language you're most comfortable with (or use it as a chance to deepen a new one). What matters is the underlying concept, not the syntax.

## How this is organized

```
cs-foundations-30-days/
├── README.md          ← you are here
├── PROGRESS.md         ← printable/checkable tracker for all 30 days
├── day-01.md ... day-30.md
```

Each `day-XX.md` file follows the same template:

- **🎯 Learning Objectives** — what you should be able to do by the end of the day
- **📚 Topics** — concepts to read up on
- **💡 Core Ideas** — the key intuitions worth internalizing, not just memorizing
- **🛠️ Practice Exercises** — hands-on implementation tasks (this is where the learning happens)
- **🎤 Interview-Style Questions** — try to answer these out loud, unaided, before checking anything
- **🔗 Resources** — where to go deeper
- **✅ Daily Checklist** — tick off as you go

## The 30-Day Arc

| Week | Days | Theme |
|---|---|---|
| 1 | 1–7 | Data Representation & Complexity — how computers work, Big-O, arrays, lists, stacks/queues, hash tables |
| 2 | 8–14 | Algorithms — recursion, backtracking, sorting, searching, trees, heaps, graphs |
| 3 | 15–21 | Advanced Algorithms & Systems — dynamic programming, greedy algorithms, operating systems, networking |
| 4 | 22–30 | Systems, Design & Practice — databases, distributed systems, system design, security, patterns, Git, testing |

Each week closes with a **capstone day** (7, 14, 21) that consolidates the week, and **Day 30** ties everything into a portfolio with a self-assessment and a plan for what's next.

## Suggested pace

- **~1.5–2.5 hours/day.** This course prioritizes depth of understanding over speed — it's fine to spend more than one day on a topic that isn't clicking.
- Do the **practice exercises for real** — implementing a hash table or binary search from scratch teaches you things that reading about them never will.
- Try the **interview-style questions out loud**, unaided, before looking anything up. Being able to explain a concept clearly, on the spot, is the actual skill interviews (and code reviews, and design docs) test for.

## Prerequisites

- Comfort writing basic programs in at least one language (loops, functions, arrays)
- A code editor and the ability to run code locally
- A place to track your work (a Git repo is strongly recommended — you'll also practice Git itself on Day 27)

## What you'll have by Day 30

- A personal data-structures library (array, linked list, stack, queue, hash map) built from scratch
- Solved problems spanning recursion, sorting, searching, trees, heaps, graphs, DP, and greedy algorithms
- Clear, written explanations of OS concurrency, networking, databases, and distributed systems fundamentals
- A complete system design write-up (`SYSTEM_DESIGN.md`) for a real system you designed end-to-end
- Practical experience with Git branching/rebasing/conflict resolution
- A testing & debugging habit grounded in the testing pyramid and systematic root-causing
- A portfolio repo tying it all together, plus a `NEXT_STEPS.md` for where to go from here

## Tips for success

1. **Implement, don't just read.** Reading about a hash table and building one from scratch teach very different things.
2. **Say your answer out loud before writing code or looking anything up.** This is the single highest-leverage interview-prep habit there is.
3. **Write things in your own words.** Every day ends with a "summarize in 2-3 sentences" checklist item — don't skip it.
4. **Revisit, don't just move on.** The Week 2 and Week 4 capstones deliberately loop back to earlier material — spaced repetition is how this actually sticks.
5. **It's a foundation, not a finish line.** Day 30 ends with a plan for what's next on purpose — 30 days builds the map, not the whole territory.
